Part 1: Introduction to Collections

What is Collections?

Collections is a framework provided by Java.

This framework provides many interfaces and their implemented classes in order to store a group of objects (elements) in a single entity.

Interfaces Provided by Collections Framework

  • Collection Interface: The root interface for most collections.
    • List <interface>
    • Set <interface>
    • Queue <interface>
  • Map Interface: Stands separate from the Collection interface, representing key-value pairs.

Classes Provided by Collections Framework

Collection Implementations

  • ArrayList
  • LinkedList
  • Vector
  • Stack
  • ArrayQueue
  • PriorityQueue
  • HashSet
  • LinkedHashSet
  • TreeSet
  • Collections (Utility Class)

Map Implementations

  • HashTable
  • HashMap
  • LinkedHashMap
  • TreeMap

Part 3: List Interface Deep Dive

1. Major Operations on Collections

Regardless of the specific list implementation you choose, you will generally perform the following six major operations:

  • Creation of a list
  • Addition of elements into the list
  • Retrieval of elements from the list
  • Deletion of elements from the list
  • Verification of elements in the list
  • Updation of elements in the list

2. Dynamic Capacity Growth: ArrayList vs Vector

Both ArrayList and Vector use dynamic arrays internally. When they reach their maximum capacity, they automatically resize by creating a new, larger array and copying the old elements over. However, their growth formulas differ significantly:

ImplementationGrowth RateMathematical Formula
ArrayList50% IncreasenewCapacity = oldCapacity + (oldCapacity >> 1)
Vector100% Increase (Doubles)newCapacity = oldCapacity * 2

3. Legacy Class: Vector & Its Methods

Vector is a legacy class introduced in Java 1.0. It is synchronized, meaning it is completely thread-safe but suffers from severe performance overhead in single-threaded environments. Aside from standard List methods, it has unique legacy methods:

  • addElement(Object o): Adds the specified component to the end of this vector.
  • firstElement(): Returns the first component (the item at index 0) of this vector.
  • lastElement(): Returns the last component of the vector.
  • removeElement(Object obj): Removes the first (lowest-indexed) occurrence of the argument from this vector.
  • removeAllElements(): Removes all components from this vector and sets its size to zero.
  • capacity(): Returns the current physical capacity of this vector array.

4. Difference Between ArrayList and Vector

FeatureArrayListVector
SynchronizationNon-synchronized (Not Thread-Safe)Synchronized (Thread-Safe)
PerformanceFast (No locking overhead)Slow (Threads must wait for lock)
Data GrowthGrows by 50% when fullDoubles (100%) when full
Legacy StatusIntroduced in Java 1.2 (Collections Framework)Legacy Class (Introduced in Java 1.0)
TraversingUses Iterator and ListIteratorUses Enumeration along with Iterators

5. Are the Methods Identical?

Yes and No. Because both ArrayList and Vector implement the List interface, all standard List operations (like add(), get(), remove(), set(), contains()) are exactly the same in both classes.

The key difference is that Vector has extra legacy methods (like addElement()) from Java 1.0 which ArrayList does not possess.

6. Code Implementation: The 6 Major Operations

Here is a complete, executable example demonstrating how to perform the six major list operations. Note: You can seamlessly swap ArrayList with Vector in this code, and it will function identically!

import java.util.ArrayList; public class ListOperations { public static void main(String[] args) { // 1. Creation of a list ArrayList<String> fruits = new ArrayList<>(); // 2. Addition of elements fruits.add("Apple"); fruits.add("Banana"); fruits.add("Mango"); System.out.println("After Addition: " + fruits); // 3. Retrieval of elements String item = fruits.get(1); // Gets the second element System.out.println("Retrieved Item: " + item); // 4. Updation of elements fruits.set(1, "Blueberry"); // Replaces Banana with Blueberry System.out.println("After Updation: " + fruits); // 5. Verification of elements boolean hasApple = fruits.contains("Apple"); System.out.println("Contains Apple? " + hasApple); // 6. Deletion of elements fruits.remove("Mango"); // Removes Mango fruits.remove(0); // Removes element at index 0 (Apple) System.out.println("After Deletion: " + fruits); } }
Expected Output:

After Addition: [Apple, Banana, Mango]
Retrieved Item: Banana
After Updation: [Apple, Blueberry, Mango]
Contains Apple? true
After Deletion: [Blueberry]

Part 4: Stack Interface Deep Dive

1. What is a Stack?

The Stack class represents a Last-In-First-Out (LIFO) stack of objects. Structurally, it is a direct child class of Vector. This means a Stack IS-A Vector, inheriting all its synchronized capabilities, but it adds five specific methods to enforce LIFO behavior.

2. The 5 Core Stack Operations

  • push(Object item): Pushes an item onto the top of this stack.
  • pop(): Removes the object at the top of this stack and returns that object.
  • peek(): Looks at the object at the top of this stack without removing it.
  • empty(): Tests if this stack is empty.
  • search(Object o): Returns the 1-based position where an object is on this stack.

3. Difference Between Vector and Stack

Because Stack extends Vector, a Stack technically possesses all Vector methods (like addElement() or get(int index)). However, logically, they represent two completely different architectures:

FeatureVectorStack
ArchitectureSequential List (Random Access)LIFO Structure (Restricted Access)
Access PatternYou can insert/remove elements at any index natively.You should strictly insert/remove at the Top only.
Primary Methodsadd(), remove(), get()push(), pop(), peek()
Search MechanismindexOf() returns a 0-based index from the front.search() returns a 1-based index strictly from the Top.

4. Code Implementation: Stack LIFO Operations

Here is an executable example demonstrating the 5 core LIFO operations. Notice how elements added last are processed first.

import java.util.Stack; public class StackOperations { public static void main(String[] args) { // 1. Creation Stack<String> books = new Stack<>(); // 2. Push (Addition) books.push("Java Core"); books.push("Spring Boot"); books.push("Microservices"); System.out.println("Stack Status: " + books); // 3. Peek (Retrieval without Deletion) String topBook = books.peek(); System.out.println("Top Book is: " + topBook); // 4. Search (Verification) // Returns 1-based position from the TOP (Microservices is 1, Spring Boot is 2) int position = books.search("Spring Boot"); System.out.println("Position of Spring Boot: " + position); // 5. Pop (Deletion) String removedBook = books.pop(); System.out.println("Popped Book: " + removedBook); System.out.println("Stack after Pop: " + books); // 6. Empty Check boolean isEmpty = books.empty(); System.out.println("Is the stack empty? " + isEmpty); } }
Expected Output:

Stack Status: [Java Core, Spring Boot, Microservices]
Top Book is: Microservices
Position of Spring Boot: 2
Popped Book: Microservices
Stack after Pop: [Java Core, Spring Boot]
Is the stack empty? false

Phase 1: LinkedList & The Queue Family

Part 5: LinkedList Deep Dive

1. What is a LinkedList?

Unlike ArrayList which uses a continuous array in memory, a LinkedList uses a Doubly-Linked List architecture. Every element is a separate object called a "Node" that contains three things: the data, a pointer to the previous node, and a pointer to the next node.

2. ArrayList vs LinkedList

FeatureArrayListLinkedList
Internal StructureDynamic Array (Continuous memory)Doubly-Linked Nodes (Scattered memory)
Search (Get)O(1) Fast - Math calculation to jump to indexO(n) Slow - Must traverse node by node
Insert/Delete in MiddleO(n) Slow - Elements must be shifted heavilyO(1) Fast - Just update pointer links
Memory OverheadLow (just stores data)High (stores data + two pointers per element)

3. Code Implementation: The Dual Nature

A LinkedList implements both the List interface AND the Deque (Double Ended Queue) interface. This means it can act like a standard list or a queue natively.

import java.util.LinkedList; public class LinkedListOps { public static void main(String[] args) { LinkedList<String> list = new LinkedList<>(); // 1. Standard List Operations list.add("Middle"); // 2. Deque Specific Operations (O(1) time complexity) list.addFirst("Front"); list.addLast("End"); System.out.println("List: " + list); // 3. Retrieval System.out.println("First: " + list.getFirst()); System.out.println("Last: " + list.getLast()); // 4. Deletion list.removeFirst(); System.out.println("After removeFirst: " + list); } }
Expected Output:

List: [Front, Middle, End]
First: Front
Last: End
After removeFirst: [Middle, End]

Part 6: PriorityQueue Deep Dive

1. What is a PriorityQueue?

A standard queue processes elements in FIFO (First-In-First-Out) order. A PriorityQueue totally ignores insertion order. Instead, it processes elements based on their Priority using a Min-Heap or Max-Heap data structure internally. By default, Java uses a Min-Heap (smallest numbers come out first).

2. Code Implementation: Natural Ordering

Notice how we insert numbers randomly, but when we remove (poll) them, they always come out in perfectly sorted (ascending) order.

import java.util.PriorityQueue; public class PQOperations { public static void main(String[] args) { // Default is Min-Heap (Smallest value has highest priority) PriorityQueue<Integer> pq = new PriorityQueue<>(); // Insertion (offer) pq.offer(50); pq.offer(10); pq.offer(30); pq.offer(5); // Note: Printing the Queue directly doesn't guarantee sorted output (it's a tree structure) System.out.println("Internal Tree Structure: " + pq); // Extraction (poll) ALWAYS retrieves the highest priority (smallest number) System.out.println("Processing Queue:"); while (!pq.isEmpty()) { System.out.println("Removed: " + pq.poll()); } } }
Expected Output:

Internal Tree Structure: [5, 10, 30, 50]
Processing Queue:
Removed: 5
Removed: 10
Removed: 30
Removed: 50

Part 7: ArrayDeque Deep Dive

1. What is an ArrayDeque?

An ArrayDeque (Double Ended Queue) is a resizable array that allows you to add or remove elements from both the front and the back. It is arguably the most powerful collection for queue operations.

  • Faster than Stack: Because it has no synchronization overhead.
  • Faster than LinkedList: Because it uses an array underneath, meaning better CPU cache locality and zero memory overhead from creating Node objects.

2. Code Implementation: The Ultimate Collection

import java.util.ArrayDeque; public class ArrayDequeOps { public static void main(String[] args) { ArrayDeque<String> deque = new ArrayDeque<>(); // --- Using it as a Fast Stack (LIFO) --- deque.push("Book1"); deque.push("Book2"); System.out.println("Stack Pop: " + deque.pop()); // Outputs Book2 deque.clear(); // --- Using it as a Fast Queue (FIFO) --- deque.offer("Person1"); deque.offer("Person2"); deque.offer("Person3"); // Polling removes from the front System.out.println("Queue Poll: " + deque.poll()); // Outputs Person1 // Deque special features deque.offerFirst("VIP_Person"); // Jumps the line deque.offerLast("Late_Person"); System.out.println("Final Queue: " + deque); } }
Expected Output:

Stack Pop: Book2
Queue Poll: Person1
Final Queue: [VIP_Person, Person2, Person3, Late_Person]

Phase 2: The Set Interface Deep Dive

Unlike Lists, Sets guarantee mathematical uniqueness. A Set absolutely cannot contain duplicate elements.

Part 8: HashSet Deep Dive

1. Internal Architecture: The "Dummy" HashMap

A HashSet is actually backed entirely by a HashMap. When you add an element to a HashSet, Java internally places it as a Key inside a HashMap, and associates it with a dummy, constant value called PRESENT.

  • Performance: O(1) Best performance for standard operations (add, remove, contains).
  • Ordering: Completely Unordered. The output sequence has absolutely no relation to insertion sequence.

2. Code Implementation: The Unordered Unique Set

import java.util.HashSet; public class HashSetOps { public static void main(String[] args) { HashSet<String> set = new HashSet<>(); // 1. Adding Elements set.add("Apple"); set.add("Banana"); set.add("Mango"); // 2. Attempting to add a duplicate boolean isAdded = set.add("Apple"); // Ignored System.out.println("Was duplicate Apple added? " + isAdded); // 3. Output is random/unordered System.out.println("HashSet Output: " + set); } }

Part 9: LinkedHashSet Deep Dive

1. Architecture: The Order Preserver

LinkedHashSet extends HashSet but maintains a Doubly-Linked List across all its elements. This allows it to preserve the exact sequence in which you inserted elements, at a slight cost to memory and speed compared to a standard HashSet.

2. Code Implementation: Preserving Insertion

import java.util.LinkedHashSet; public class LinkedHashSetOps { public static void main(String[] args) { LinkedHashSet<String> lhSet = new LinkedHashSet<>(); lhSet.add("Apple"); lhSet.add("Banana"); lhSet.add("Mango"); // Output maintains EXACT insertion order System.out.println("LinkedHashSet Output: " + lhSet); } }

Part 10: TreeSet Deep Dive

1. Architecture: The Red-Black Tree

TreeSet implements the NavigableSet interface. It stores elements internally inside a Self-Balancing Binary Search Tree (Red-Black Tree). Because it must continuously balance the tree during insertions, its performance drops to O(log n), but it provides powerful automatic sorting.

2. Code Implementation: Automatic Sorting

import java.util.TreeSet; public class TreeSetOps { public static void main(String[] args) { TreeSet<Integer> tree = new TreeSet<>(); // Inserting Randomly tree.add(50); tree.add(10); tree.add(40); tree.add(20); // Outputs in perfect numerical order System.out.println("TreeSet Output: " + tree); // Powerful NavigableSet Methods System.out.println("Highest number below 40: " + tree.lower(40)); System.out.println("Lowest number above 40: " + tree.higher(40)); } }
Expected Output Summary:

HashSet: [Banana, Apple, Mango] // (Random)
LinkedHashSet: [Apple, Banana, Mango] // (Inserted Order)
TreeSet: [10, 20, 40, 50] // (Sorted Order)
TreeSet Navigable: 20, 50

Phase 3: The Map Interface Deep Dive

Maps DO NOT implement the Collection interface. They are a separate entity designed to store data in Key-Value pairs. Keys must be strictly mathematically unique, while Values can be duplicated limitlessly.

Part 11: HashMap Deep Dive

1. Architecture: Buckets & Hashing

A HashMap uses an internal Array of "Buckets". When you `put(Key, Value)`, it runs the Key through a hashCode() algorithm to determine exactly which bucket to drop the data into. If a "Hash Collision" occurs (two keys get the same hash), it creates a LinkedList (or a balanced tree in Java 8+) inside that specific bucket.

  • Performance: O(1) Extremely fast retrieval.
  • Ordering: Completely Unordered. Keys are scrambled based on their hash algorithms.
  • Nulls: Allows exactly ONE null Key, and unlimited null Values.

2. Code Implementation: The Dictionary Pattern

import java.util.HashMap; public class HashMapOps { public static void main(String[] args) { HashMap<String, Integer> map = new HashMap<>(); // 1. Adding Key-Value Pairs map.put("Alice", 95); map.put("Bob", 80); map.put("Charlie", 90); // 2. Handling Duplicate Keys (Overwrites the old value) map.put("Alice", 99); // 3. Retrieval int alicesScore = map.get("Alice"); System.out.println("Alice's Score: " + alicesScore); // 4. Verification System.out.println("Has Bob? " + map.containsKey("Bob")); // 5. Iteration (Getting all keys) System.out.println("All Students: " + map.keySet()); // Output is structurally Unordered System.out.println("Full Map: " + map); } }

Part 12: LinkedHashMap Deep Dive

1. Architecture: The Order Cache

A LinkedHashMap is identical to a HashMap but wires a Doubly-Linked List through all its entries. It is heavily used to build Caches (like LRU Cache) because it perfectly preserves the Insertion Order of the Keys.

Part 13: TreeMap Deep Dive

1. Architecture: The Sorted Dictionary

A TreeMap internally utilizes a Red-Black Tree. It completely ignores insertion order and instead automatically Sorts all entries based on the natural ordering of the Keys (e.g., A-Z for Strings, 1-100 for Integers).

Part 14: HashTable (Legacy Class) Deep Dive

1. HashMap vs HashTable

HashTable is the legacy equivalent of HashMap from Java 1.0. Just like Vector is to ArrayList, HashTable is the synchronized, slow predecessor to the modern HashMap.
